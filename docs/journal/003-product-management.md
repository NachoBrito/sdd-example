# Feature Journal: Product Management

This document records the development process for the Product Management feature.
The feature adds the Product aggregate and the REST API to the service.

## 1. Implementation Process

The implementation followed the Spec-Driven Development workflow.

First, the agent created the feature specification.
The specification defines the Product aggregate, the attributes, and the REST endpoints.
The user clarified the deletion behavior, the price validation rules, and the SKU scope.

Next, the agent created the implementation plan and the task list.
The design followed the hexagonal architecture and the domain-driven design principles.

Then, the agent implemented the software layers in sequence:
- The agent created the Liquibase migration for the database table.
- The agent built the domain model and the domain validation rules.
- The agent implemented the application use cases and the service.
- The agent built the persistence adapter with Micronaut Data JDBC.
- The agent created the REST controller, the DTO records, and the error handler.
- The agent created the unit test suite and the integration test suite.

Finally, the agent executed the quality checks and verified the acceptance criteria.

## 2. Bugs Found

The agent found two technical bugs during implementation.

### SQL Table Alias in Repository Query
The custom search query failed during dynamic sorting.
Micronaut Data JDBC appends order clauses that reference the table alias `product_entity_`.
The original query selected from `products` without this alias.
The MariaDB server rejected the query because the column name was unknown.
The agent added the alias `product_entity_` to the SQL query.
The tests passed after this change.

### Void Method Call in Controller
The unit test for the delete endpoint verified only the HTTP status code.
Pitest detected that the controller could omit the service call without test failure.
The agent added verification for the port invocation.
This assertion killed the mutation.

## 3. Static Code Analysis Issues

The static code analysis tools identified several violations across the codebase.

### Java Compiler Warnings
The compiler option `-Werror` failed on third-party classfiles and generated code.
The Jackson serialization annotations generated raw types, unchecked operations, and redundant casts.
The user authorized compiler arguments to ignore `-classfile`, `-rawtypes`, `-unchecked`, and `-cast`.

### Checkstyle Violations
Checkstyle reported lines that exceeded 100 characters.
The agent wrapped method annotations, SQL queries, and test assertions.
Checkstyle also rejected the `IT` suffix in test class names.
The agent renamed the integration test classes to use the `TestCase` suffix.

### PMD Violations
PMD found excessive imports and object coupling in the REST controller.
The agent resolved this issue with two changes:
- The agent moved the error handlers to `ProductExceptionHandler`.
- The agent combined the inbound interfaces into the composite port `ProductUseCase`.

PMD also required the `@FunctionalInterface` annotation on single-method interfaces.
The agent added the annotation to all five use case interfaces.
The agent also fixed string case conversions by providing `Locale.ROOT`.
The agent preserved cause exceptions when throwing `InvalidProductDataException`.
The agent split large test classes to satisfy the method count limit.
The agent ensured that every test method contains only one assertion.

### SpotBugs Violations
SpotBugs detected potential vulnerabilities in constructors that throw exceptions.
The agent removed validation checks from constructors where Micronaut manages injection.
SpotBugs also reported mutable state exposure in `ErrorResponse`.
The agent converted the details list to an unmodifiable collection.

SpotBugs reported false positives on synthetic classes generated by Micronaut.
The user authorized exclusions in `config/spotbugs/exclude.xml` for generated classes.
The exclusions cover `*Serde*` serializers and `*Intercepted` repositories.

## 4. Test Coverage and Mutation Testing

The project requires a minimum of 80 percent line coverage.
The project also requires a minimum of 90 percent mutation score.

Initially, Pitest reported only 11 percent line coverage.
Pitest targets the complete package but excludes integration tests.
The adapters and controllers had integration tests but lacked unit tests.

The agent created isolated unit tests for all components:
- The agent added `ProductControllerTest`.
- The agent added `ProductPersistenceAdapterCommandTest` and `ProductPersistenceAdapterQueryTest`.
- The agent added `ProductEntityTest`.
- The agent added `ProductExceptionHandlerTest`.
- The agent added `ErrorResponseTest` and `ProductResponseTest`.

The agent used parameterized tests with boolean values to kill return value mutants.
The agent tested boundary conditions for all maximum field lengths.
These tests verified strings of 100, 255, and 4000 characters.

The final verification achieved:
- **Line coverage**: 98 percent (222 of 226 lines covered).
- **Mutation score**: 91 percent (111 of 122 mutations killed).

All automated checks passed successfully.
