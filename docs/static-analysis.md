# Static Analysis and Code Quality

This document describes the static analysis tools, rules, and thresholds for the project.
Every build executes all checks.
The build fails when any check detects a violation.

## 1. Java Compiler Checks

The build configures the Java compiler with strict options:

- `-Xlint:all,-processing`: The compiler activates all standard lint warnings. The `processing` category is disabled because annotation processors report unclaimed options.
- `-Werror`: The compiler terminates the build when any warning occurs.
- `-parameters`: The compiler preserves parameter names in the bytecode for dependency injection and reflection-free introspection.

## 2. Checkstyle

Checkstyle enforces the source code layout and naming standards.

- **Tool version**: 14.4.0.
- **Rule set**: Google Java Style Guide (`config/checkstyle/google_checks.xml`).
- **Severity**: Errors (`org.checkstyle.google.severity = error`).
- **Threshold**: 0 warnings and 0 errors allowed (`maxWarnings = 0`, `maxErrors = 0`).
- **Exclusions**: Source files generated by annotation processors in `build/generated/`.

## 3. PMD

PMD detects common programming flaws, design issues, and unused code.

- **Tool version**: 7.29.0.
- **Rule set file**: `config/pmd/ruleset.xml`.
- **Minimum priority**: 5 (evaluates all rule priorities from 1 to 5).
- **Rule categories**:
  - `category/java/bestpractices.xml`
  - `category/java/codestyle.xml`
  - `category/java/design.xml`
  - `category/java/documentation.xml`
  - `category/java/errorprone.xml`
  - `category/java/multithreading.xml`
  - `category/java/performance.xml`
  - `category/java/security.xml`

### PMD Exclusions and Rationale

The configuration disables specific rules that conflict with modern Java or project conventions:

- `AtLeastOneConstructor`: Java records provide canonical constructors automatically.
- `MethodArgumentCouldBeFinal` and `LocalVariableCouldBeFinal`: Google Java Style omits redundant `final` keywords on method arguments and local variables.
- `OnlyOneReturn`: Guard clauses improve code readability.
- `ShortVariable` and `LongVariable`: Variable length does not indicate quality.
- `UseExplicitTypes`: Type inference with `var` is permitted when type is obvious.
- `CallSuperInConstructor`: Micronaut constructor injection does not require calling super constructors.
- `TooManyStaticImports`: Tests require static imports for assertion methods and architecture DSLs.
- `LocalVariableDeclarationShouldBeAtStartOfBlock`: Google Java Style and Effective Java mandate declaring variables close to their point of use.
- `CommentDefaultAccessModifier`: JUnit 5 test classes and package-private methods do not require comments for default visibility.
- `FieldNamingConventions`: ArchUnit rule objects are static final instances named with camelCase notation.
- `LinguisticNaming`: Fluent predicate and condition builder methods in tests and domain logic use descriptive verbs.
- `LawOfDemeter`: Fluent builder APIs and domain value objects legitimately chain operations.
- `DataClass`: Domain records and data transfer objects legitimately act as immutable data containers.
- `LoosePackageCoupling`: Package coupling is verified by the stricter ArchUnit layer rules.
- `InstantiableUtilityClass`: ArchUnit test classes are instantiated by the test runner.
- `CommentRequired` and `CommentSize`: Checkstyle manages Javadoc requirements.
- `TestClassWithoutTestCases`: ArchUnit test classes declare `@ArchTest` fields rather than `@Test` methods.
- `AvoidDuplicateLiterals`: Package names and architectural layer names repeat legitimately in configuration and tests.
- `AvoidUsingHardCodedIP`: Prevents false positive detections on version string patterns like `1.2.3.4`.
- `UnitTestContainsTooManyAsserts`: Tests legitimately verify multiple properties on data objects and payloads.
- `TooManyMethods`: Comprehensive test suites and domain aggregates legitimately declare more than 10 methods.

## 4. SpotBugs

SpotBugs performs static bytecode analysis to find bug patterns.

- **Tool version**: 4.10.5.
- **Effort level**: `Effort.MAX`.
- **Confidence threshold**: `Confidence.LOW` (reports all confidence levels).
- **Failure policy**: `ignoreFailures = false`.
- **Exclusion filter**: `config/spotbugs/exclude.xml` ignores only synthetic classes generated by Micronaut annotation processors (classes containing `.$`).

## 5. ArchUnit

ArchUnit enforces hexagonal architecture constraints and library restrictions at test time.

- **Tool version**: 1.5.1.
- **Test location**: `src/test/java/es/nachobrito/sdd/example/architecture/HexagonalArchitectureTest.java`.
- **Enforced architectural rules**:
  1. **Layer dependencies**:
     - `Domain` is accessed only by `Application` and `Adapter`.
     - `Application` is accessed only by `Adapter`.
     - `Adapter` is not accessed by any layer.
  2. **Domain isolation**:
     - `Domain` must not depend on external frameworks. It only depends on `java..` and `org.jspecify..`.
  3. **Application isolation**:
     - `Application` must not depend on transport, persistence, or messaging libraries. Infrastructure access occurs solely through ports.
  4. **Adapter segregation**:
     - Inbound adapters must not depend on outbound adapters.
     - Outbound adapters must not depend on inbound adapters.
  5. **Cycle prevention**:
     - Package slices must be free of cyclic dependencies.
  6. **Micronaut-native enforcement**:
     - Code must not depend on `jakarta.persistence..`, `javax.persistence..`, `org.hibernate..`, `lombok..`, or `com.fasterxml.jackson.databind..`.
  7. **REST API conventions**:
     - `@Controller` classes must reside in `..adapter.in.rest..`.
     - `@Controller` paths must match the versioned path pattern (`/v1/...`, `/v2/...`).
  8. **Persistence conventions**:
     - `@Repository` interfaces must reside in `..adapter.out.persistence..`.
  9. **Messaging conventions**:
     - `@RabbitListener` classes must reside in `..adapter.in.messaging..`.
     - `@RabbitClient` interfaces must reside in `..adapter.out.messaging..`.
  10. **General coding practices**:
      - No direct calls to standard output or error streams (`System.out`, `System.err`).
      - No throwing of generic exceptions (`Exception`, `Throwable`, `RuntimeException`).
      - No usage of `java.util.logging` (use SLF4J instead).
      - No field injection (use constructor injection).
      - No usage of legacy date libraries (`org.joda.time`).

## 6. Pitest (Mutation Testing)

Pitest executes mutation tests to measure the strength of the test suite.

- **Tool version**: 1.30.2.
- **JUnit 5 plugin**: 1.2.3.
- **Target classes**: `es.nachobrito.sdd.example.*`.
- **Excluded classes**: Application launcher (`Application`) and generated classes (`$*`).
- **Excluded test classes**: Architecture tests (`*architecture.*`) and integration tests (`*IT`).
- **Mutators**: `STRONGER`.
- **Coverage threshold**: 80% line coverage minimum.
- **Mutation threshold**: 90% mutation score minimum.
- **Fail policy**: `failWhenNoMutations = true`.
- **Build lifecycle**: Attached directly to the Gradle `check` lifecycle task.

## 7. Execution Commands

Execute all static analysis checks with the standard Gradle command:

```bash
./gradlew check
```

Execute a complete build including packaging and verification:

```bash
./gradlew build
```
